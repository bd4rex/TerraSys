# 资源与地图版本管理

> [English](RESOURCE_AND_VERSION_MANAGEMENT.md) | 简体中文 · 快照 `2026-08-03T23:12:23+08:00`

## 入口

- 地图：`http://localhost:8080/`
- 资源与版本：`http://localhost:8080/resources.html`

地图页面负责浏览、搜索、个人点位、轨迹和路线；资源页面负责获取内容、已安装产品、版本历史、磁盘分类、维护任务和更新检查。

## 地图包状态

每个区域使用稳定的 `resourceId` 管理。完整安装至少包含：

- `products/tiles/pmtiles/<id>.pmtiles`
- `products/tiles/pmtiles/<id>.manifest.json`

清单记录源路径、复制序列与时间、构建时间、字节数、SHA256、边界、工具来源和可选高细节叠加信息。只有产品与清单形成有效配对时，API 才认定地图已安装。

版本视图区分：

- **当前版**：已启用 PMTiles 和清单；
- **上游版**：最近一次可信复制状态；
- **回退版**：与当前版不同的最近完整产品/清单；
- **历史**：不重复保存大文件的小型来源记录；
- **暂存**：不计为已安装的未完成构建。

## 更新不变量

大陆省份共用一份已校验中国 OSM 快照。只有可信上游序列变化时才重新下载；同序列的排队省份更新复用本地文件。

激活顺序：

1. 下载到 PBF 暂存路径；
2. Osmium 完整扫描并核对复制序列；
3. 原子激活共享源并保留上一份；
4. 提取单一区域，生成基础与高细节暂存 PMTiles；
5. 校验首部、元数据、字节数和哈希；
6. 原子激活当前地图及清单；
7. 持久保存明确成功或失败结果。

已经是当前序列时，更新返回 `409`。源未变化但要重新生成时使用“重建”，不能把重复构建显示为新的上游版本。

## 任务与地图联动

资源页轮询轻量维护快照，不主动触发磁盘扫描。每行显示自己的队列/耗时、阶段、实测速率、取消与重试。无法测量时只显示“处理中”，不伪造百分比。

地图变化通过本地 `terrasys-resource-revision` 通知其他标签页。标签页刷新地图包状态，但用户编辑点位或路线时不会强制重载 PMTiles。

Nominatim 与 Valhalla 使用蓝绿版本。候选受到资源限制并串行构建，验证点根据已启用覆盖动态产生，不再固定检查某个国家。候选必须通过路线健康、Nominatim 数据库完整性、搜索/反查和 API 就绪检查后才能切换。失败或取消保留当前版本，默认保留一个上一版本。

共享索引失败或工作器重启后不会自动重试。

## 启用、回退与删除

- **停用**：保留地图和来源，但停止渲染并移出共享索引目标范围。
- **启用**：把已校验地图重新加入渲染，并可能标记共享索引过期。
- **回退**：原子交换当前与上一完整版本，原当前版成为新的回退目标。
- **受保护删除**：要求资源 ID 确认，只删除当前/回退派生地图，保留区域 PBF 和边界用于断网重建。

## 磁盘分类

盘点分别统计当前地图、回退地图、暂存输出、版本清单、共享 OSM、源回退、路线/搜索、OSM Carto、知识库、备份、完整恢复包和可再生缓存。

每项有四个稳定字段：

- `resourceType`：是什么；
- `storageClass`：承担 `primary`、`rollback`、`staging` 或 `cache` 等角色；
- `scope`：`regional`、`global`、`system` 或 `personal`；
- `validationPolicy`：称为有效资源的条件。

这些定义集中在 `services/api/app/main.py` 的 `RESOURCE_CLASSIFICATIONS`，界面文字变化不会影响分类语义。

## 有效性规则

“文件存在”不等于“资源有效”：

- **就绪**：清单、字节、必要哈希和服务满足策略；
- **需检查**：文件存在但依赖过期、服务不可用或校验不完整；
- **外部卷/系统能力**：数据位于 Docker 或浏览器运行时，不冒充宿主机文件；
- **未安装**：没有达到最小完整性；
- **缓存**：可删除并再生，不属于灾备基线。

具体规则：

- 当前/回退地图必须产品与清单成对且字节一致，完整 SHA256 异步执行；
- OSM 源通过完整 Osmium 与复制状态检查后才激活；
- HGT 文件名和网格字节必须有效；
- 概览、天气、航海要求清单、字节和哈希一致；
- 百科与旅行指南独立计量，并要求 Kiwix 健康；
- 搜索与路线必须覆盖所有启用包；只含多余旧范围时可用但提示清理；
- 恢复包必须逐文件 SHA256 通过，且 `verification.json` 绑定当前 manifest；
- OSM Carto 要求来源记录、健康数据库和可用本地瓦片端点。

`verification.json` 不进入自身 manifest。重新校验先删除旧凭据，中断会让恢复包重新显示为未验证。
