# 可靠性升级说明

> [English](RELIABILITY_FIXES.md) | 简体中文 · 2026-09-06

本次修改对应九月项目审查中的可靠性问题，包含源码修复和回归测试。数据库迁移、镜像重建、大体积离线包刷新，以及完整服务验收属于部署步骤。

| 审查项 | 修复与回归覆盖 |
| --- | --- |
| 1、2、5：个人恢复、地图回滚和构建取消 | 个人数据库事务恢复与安全检查点；地图候选版本完整校验、操作锁、激活日志和可重试恢复。故障注入覆盖文件发布及恢复失败。 |
| 3、6：离线包遗漏和镜像版本不一致 | 创建、刷新和校验共用文件与镜像清单；验证空目录恢复、必需输入遗漏、重复刷新和镜像不匹配。 |
| 4：MCP 初始化阻塞 | 改为逐行 UTF-8 JSON-RPC，验证 stdin 保持打开时立即响应，以及通知、坏报文和后续请求。 |

| 9、10：里程误差和附近地点漏查 | 使用 geography 距离与空间索引，并提供历史里程迁移；真实 SQL 回归覆盖中高纬度及日期变更线。 |

## 升级与恢复

1. 部署更新前，先创建并校验个人备份。使用正常入口 `start-terrasys.cmd` 或 `./terrasys.sh start` 重启，使 API 镜像与有序迁移得到更新。
2. 迁移 `008_geography_distances.sql` 使用测地距离重算已存轨迹，并为附近地点查询增加索引。被修正的轨迹按现有规则更新版本和历史；重复执行不会再次修改正确记录。迁移后应重新加载已打开的轨迹编辑器。
3. 地图构建先完成并校验基础地图、详情和候选清单，再发布。短暂的激活日志让 API 避开未完成的提交。启动、维护恢复及后续地图操作会利用保留的快照修复中断提交。未解决的 `<pack>.activation.json` 应与其私有快照目录一起保留。
4. 个人恢复使用事务，并在 `data/restore-recovery/` 保留安全数据库转储与原媒体。若启动提示恢复中断，在项目目录运行 `pwsh -File scripts/restore-terrasys.ps1 -RecoverInterrupted`，回退该操作。恢复成功前保留日志与检查点，不要绕过检查手动启动读取服务。
5. 重新生成或刷新离线包到 schema v5。`config/offline-kit.json` 统一项目文件和构建镜像清单。所需镜像集合发生变化时，刷新必须同时更新归档；`-SkipDockerImages` 会在修改旧包前拒绝不兼容的镜像归档。旧格式包仍可校验已记录文件，但会明确提示项目完整性未经验证。

离线校验分别报告 `projectComplete` 和 `rebuildReady`。不包含 Docker 镜像的包可以拥有完整项目文件，但 `rebuildReady=false`。实际断网恢复与重建能力仍需针对真实归档数据和镜像运行隔离演练。地图复制会拒绝正在执行或已中断的版本提交，并拒绝与构建清单 SHA256 不符的源文件。

AIS 不再在 API 启动时连接外网；地图请求或显式连接测试才启动接收。管理页停用会停止接收，无后续请求时按刷新周期计算的租期结束连接。停用图层的 API 不查询上游。实时数据内存缓存最多保留 128 项，并执行过期和 LRU 淘汰。

## 验证

在虚拟环境安装 `tests/requirements.txt`，再运行 `tests/run-suite.ps1 -Profile static -PythonExecutable <虚拟环境Python路径>`。该 profile 包含临时目录与模拟 Docker 的故障注入、FastAPI 事务夹具、标准 MCP 子进程、实时图层测试和隔离 Node 请求顺序测试。

独立 PostGIS CI job 在空的 `terrasys_reliability_test` 数据库中执行距离、附近查询及迁移检查。本机未设置 `TERRASYS_TEST_DATABASE_URL` 时，这些 SQL 测试会明确跳过。浏览器/full/recovery 层见[测试指南](../tests/README.zh-CN.md)。隔离测试通过后，发布前仍需验证真实容器、大体积地图、媒体及离线归档。
