# 较弱模型全能力重建执行手册

> [English](AI_REBUILD_EXECUTION_PLAN.md) | 简体中文
>
> 文档快照：`2026-08-07T14:04:59+08:00`

本手册用于让能力明显弱于当前开发模型的其他平台模型，从空仓库重建 GIS_P 的全部可观察能力。目标是功能、数据契约、离线行为、恢复能力和运维体验等价，不要求逐行复制实现。

本手册不是一个可以一次性提交给模型的超长需求。正确用法是：先发送“固定系统提示词”，然后每次只发送一个工作包提示词；当前工作包的测试通过并形成检查点后，才能进入下一个工作包。

## 1. 成功定义

重建完成必须同时满足以下条件：

1. 只有 `http://127.0.0.1:8080` 对宿主机开放；PostGIS、Martin、FastAPI、Nominatim、Valhalla、Kiwix 和 OSM Carto 只在容器网络中通信。
2. 已准备本地资源后，地图、个人数据、搜索、路线、地形、天气、航海、知识库、备份与恢复可以断网运行。
3. 个人 PostGIS 数据和内容寻址媒体是权威数据；地图、索引、天气和缓存是可重建产品。
4. 所有派生产品遵守“暂存 → 验证 → 激活 → 保留回退”顺序，失败或取消不替换当前版本。
5. 浏览器只能提交固定资源 ID 和白名单动作，不能执行任意命令或直接访问数据库。
6. 区域目录、清单、API、数据库迁移、资源状态和错误语义保持稳定。
7. `static`、`browser`、`full`、`recovery` 四层测试全部通过，并保存可审计证据。
8. 中英文文档成对、互链，命令、路径、版本和时间戳一致。

## 3. 弱模型执行约束

这些约束用于补偿较弱模型在长上下文、跨文件推理和失败恢复方面的不足。

### 3.1 每轮只做一个原子任务

- 一轮最多修改 8 个文件；超过时先拆任务。
- 一轮只引入一个数据库迁移、一个 API 能力组、一个界面流程或一个运维动作。
- 不允许同时重构、增加功能和更新依赖。
- 先读取相关文件，再给出修改计划；没有证据时不得声称“已经存在”或“已经通过”。
- 每轮结束必须执行目标测试和最小回归测试。

### 3.2 固定上下文包

每轮只提供：

1. `PROJECT_CONTRACT.md`：不可破坏的架构和安全不变量；
2. `REBUILD_STATUS.md`：完成项、当前项、阻塞项、最近测试结果；
3. 当前工作包指定的 3–8 个源文件；
4. 对应测试和失败日志；
5. 明确的输入、输出、禁止事项和验收命令。

模型不得依赖未提供的聊天历史。每轮完成后，用“交接提示词”压缩状态并写入 `REBUILD_STATUS.md`。

### 3.3 证据优先

“完成”的唯一依据是：文件 diff、命令退出码、结构化测试结果、HTTP 响应、数据库查询、截图或恢复审计。界面看起来合理、容器处于 running、模型自述完成都不算验收。

### 3.4 双模型或双轮审查

如果平台只能使用同一个弱模型，同一工作包至少运行两轮：

1. 实现轮：只实现验收范围；
2. 审查轮：新上下文读取 diff 和测试，从契约反向寻找遗漏。

审查轮不能直接接受实现轮的总结，必须读取实际文件和测试输出。

## 4. 固定提示词

### 4.1 执行模型系统提示词

在每个工作包前粘贴以下内容：

```text
你是 GIS_P 重建项目的执行工程师。你的能力有限，因此必须依靠小步修改、显式契约和自动化测试工作。

总规则：
1. 先读取我列出的文件和日志，再提出不超过 7 步的本轮计划。
2. 本轮只能完成一个工作包，不得顺手重构其他区域。
3. 保留现有行为和用户改动；禁止重置、覆盖或删除不属于本工作包的内容。
4. 所有数据替换必须使用“暂存、验证、原子激活、保留回退”。失败或取消不得改变活动版本。
5. 个人 PostGIS 与内容寻址媒体是权威数据；地图和索引是可重建产品。
6. 浏览器不得持有数据库凭据或提交任意宿主机命令。
7. 只允许 nginx 绑定 127.0.0.1:8080；不得扩大网络暴露面。
8. 所有坐标使用 WGS84 经度/纬度；不要交换纬度和经度。
9. 不得伪造测试、进度、哈希、下载速度或服务状态。
10. 修改后运行我指定的验收命令。测试失败时先定位根因，不得删除断言来获得绿色结果。

最终回答严格包含：
- Outcome：完成或未完成；
- Changed files：逐文件说明；
- Contract decisions：本轮保持了哪些不变量；
- Tests：命令、退出码、关键输出；
- Remaining risks：仍未验证的内容；
- Next context：下一轮只需要读取的文件。
```

### 4.2 审查模型提示词

```text
你是独立审查者。不要相信实现者的总结，只审查实际 diff、相关源文件、测试和日志。

任务：
1. 从验收标准逐条建立“要求 → 实现位置 → 测试证据”映射。
2. 寻找静默降级、硬编码区域、假进度、缺少回退、路径穿越、错误坐标、未清理临时数据、公开端口和文档漂移。
3. 只报告可以定位到文件和行为的缺陷，按 P0/P1/P2 排序。
4. 如果没有阻塞项，明确写出尚未覆盖的风险，而不是简单回答“没问题”。
5. 不修改代码。输出最小修复建议和应该新增的回归断言。
```

### 4.3 失败修复提示词

```text
当前工作包的验收失败。只修复这个失败，不扩展功能。

输入包括：失败命令、完整错误、最近 diff、相关源文件和预期契约。
请先给出：最可能的三个根因、区分它们的最小只读检查、检查结果。
确认根因后实施最小修复，保留失败前可用版本，重新运行失败测试和它的上一层回归测试。
禁止通过放宽断言、增加任意 sleep、吞掉异常、返回固定成功值或跳过测试来修复。
```

### 4.4 阶段交接提示词

```text
请为下一轮生成不超过 120 行的 REBUILD_STATUS.md 更新，只记录可验证事实：
- 当前提交与工作区状态；
- 已完成工作包及证据；
- 未完成工作包；
- 已知风险和失败；
- 活动数据版本与回退版本；
- 下一工作包需要读取的最多 8 个文件；
- 下一步唯一验收命令。
不要复制聊天记录，不要写推测，不要把“容器运行”写成“功能通过”。
```

## 5. 阶段计划与逐步提示词

预计采用 9 个阶段（阶段 0–8）、24 个工作包。每个工作包完成后建立 Git 检查点；阶段门未通过时不得进入下一阶段。

### 阶段 0：冻结基线和建立能力账本

#### WP-00 建立可观察基线

目标：把参考项目变成可验证的需求来源，而不是依赖记忆。

```text
工作包 WP-00：建立 GIS_P 能力基线，不修改产品代码。

读取 README、ARCHITECTURE、CONFIGURATION、DATA_PIPELINE、OPERATIONS、REBUILD、测试目录、Compose 和 FastAPI 路由。
生成：
1. PROJECT_CONTRACT.md，列出网络、数据所有权、版本切换、坐标、资源覆盖和安全不变量；
2. CAPABILITY_MATRIX.md，列出每项能力、用户入口、API/脚本、持久数据、依赖服务、失败回退、现有测试；
3. API_BASELINE.json，记录方法、路径、成功状态码、关键字段和典型错误；
4. REBUILD_STATUS.md，状态全部从“未开始”起步。

不得复制密钥、机器专属路径中的数据或大体积派生产品。对无法观察的行为标记 unknown，不能猜测。
验收：所有能力都能映射到至少一个入口和一个测试计划；JSON 可解析；文档相对链接有效。
```

#### WP-01 采集黄金样本

```text
工作包 WP-01：从已运行参考系统采集最小黄金样本，不实现功能。

为 /api/health、/api/status、/api/capabilities、/api/map-packs、/api/resources、个人数据 CRUD、搜索、路线、海拔、天气和航海保存去除时间戳/随机 ID 后的契约样本。采集 PMTiles Range 206 响应头、Martin catalog、数据库迁移列表和四个关键界面截图。

个人数据样本只使用测试记录，结束时清理并核对计数恢复。不得导出真实个人数据或 secrets。
输出 GOLDEN_SAMPLES.md、脱敏 JSON fixture 和采集命令。每个样本记录采集时间、参考提交和规范化规则。
```

阶段门 G0：能力矩阵无未归类入口；黄金样本可重复采集；参考系统数据计数未改变。

### 阶段 1：仓库骨架、CI 和运行边界

#### WP-02 创建仓库骨架

```text
工作包 WP-02：创建最小可测试仓库骨架。

建立 config、services、scripts、web、tests、docs 和 .github/workflows。提供中英文 README、许可证/来源占位说明、.gitignore 和无密钥的 services/.env.example。创建 static 测试入口，检查 JSON/YAML、PowerShell 语法、双语文档配对、相对链接和测试目录完整性。

禁止加入业务实现、真实密码、下载数据或空的“永远成功”测试。
验收：空白业务仓库仍能运行 static；故意破坏一个 JSON 时测试必须失败，恢复后通过。
```

#### WP-03 建立 Compose 与单入口

```text
工作包 WP-03：实现八服务 Compose 拓扑和 nginx 单入口。

服务名：web、api、postgis、martin、nominatim、valhalla、kiwix、osm-carto。第三方镜像固定 digest；只有 web/nginx 发布 127.0.0.1:8080。配置内部 DNS、健康检查、只读挂载和命名卷。nginx 路由 /、/api/、/martin/、/wiki/、/carto/ 和 /tiles/，拒绝 dotfile，并为 PMTiles 支持 Range。

不要实现业务 API。先使用最小健康占位容器验证拓扑，但占位必须在 WP-04 后删除。
验收：docker compose config 成功；宿主机端口扫描只看到 127.0.0.1:8080；内部服务不绑定 0.0.0.0 到宿主机。
```

#### WP-04 密钥、启动和迁移入口

```text
工作包 WP-04：实现幂等启动、停止、密钥和迁移入口。

缺失 services/.env 时生成独立的 32 字节随机 POSTGRES_PASSWORD 和 NOMINATIM_PASSWORD；已有文件不得覆盖。start-giss 依次启动 PostGIS、等待健康、同步角色密码、执行有序迁移、启动核心服务；stop-giss 可重复执行。所有 PowerShell 原生命令必须检查退出码。

验收：连续启动两次不改密码、不重复迁移、不丢数据；停止两次不报破坏性错误；.env 未被 Git 跟踪。
```

阶段门 G1：`static` 通过；Compose 解析；仅 loopback 单入口；重复启动保持相同数据库和密钥。

### 阶段 2：个人权威数据和 API 基础

#### WP-05 数据库迁移和发布视图

```text
工作包 WP-05：实现可重放 PostGIS 迁移。

按顺序建立 app.places、app.tracks、app.media、app.change_log、app.reference_places、app.dataset_state、app.collections、app.place_collections，以及 app.places_web 和 app.tracks_web。加入 PostGIS、pg_trgm、GiST/GIN 索引、更新时间触发器、行级变更记录和迁移登记表。

迁移必须幂等且 ON_ERROR_STOP；已有数据升级不能 drop/recreate。Martin 只允许两个批准视图。
验收：空库迁移、重复迁移和从前一迁移版本升级都通过；系统表与私有表不出现在 Martin catalog。
```

#### WP-06 FastAPI 基础契约

```text
工作包 WP-06：实现 FastAPI 基础、连接池和统一错误契约。

只实现 /health、/status、/capabilities。使用固定依赖版本、参数化 SQL、连接池和明确超时。健康响应区分 API 存活、数据库可用和能力准备状态；不要把“未安装高级资源”伪装成错误，也不要把异常吞成 200。

验收：数据库正常、数据库不可达和部分能力未准备三种 fixture 都返回匹配契约的状态；日志不包含密码或连接串。
```

#### WP-07 点位、轨迹与集合生命周期

```text
工作包 WP-07：实现个人点位、轨迹和集合的完整生命周期。

实现点位/轨迹 GeoJSON 查询，点位和轨迹创建、更新、删除，集合 CRUD 和成员关系。坐标为 WGS84 经度/纬度；更新使用 version 乐观锁，旧版本返回冲突；所有写操作进入 change_log。搜索先支持个人点位和轨迹。

每个 API 先写失败测试再实现。测试使用唯一前缀并在 finally 清理。
验收：CRUD、空间查询、集合成员、版本冲突、非法几何、清理后计数恢复全部通过。
```

#### WP-08 媒体、导入和导出

```text
工作包 WP-08：实现媒体、GPX 导入和可移植导出。

图片上传限制 64MB，先安全解码，再以 SHA256 命名；多个元数据记录允许共用物理文件，最后一个所有者删除后才清理。GPX 使用安全 XML 解析。提供单轨迹 GPX、全部 GPX、GeoJSON 和包含 manifest/SHA256 的 ZIP 导出。

拒绝路径穿越、ZIP slip、伪装图片、超限文件和 XML 外部实体。失败上传不得留下临时文件。
验收：重复媒体、双所有者、孤儿清理、恶意文件、导出内容和 SHA256 全部有自动化测试。
```

阶段门 G2：个人数据生命周期测试通过；迁移可重放；Martin 白名单正确；临时记录和文件清理为零残留。

### 阶段 3：地图目录、区域产品和浏览器地图

#### WP-09 目录与 manifest 契约

```text
工作包 WP-09：实现区域目录和地图包状态机。

建立中国 34 个省级单元、全球 Geofabrik 层级、渲染配置和资源目录。定义稳定 resourceId、边界、来源、成员和构建估算。地图只有 PMTiles 与 manifest 同时存在，且字节/首部/元数据满足策略时才是 installed。

实现 available、staged、installed、disabled、update-available、rollback 和 invalid 状态。禁止仅凭文件存在或容器健康判断就绪。
验收：目录数量、ID 唯一性、父子关系、台湾省中文规范化、缺 manifest、字节漂移和无效 PMTiles fixture 均有断言。
```

#### WP-10 区域构建和原子激活

```text
工作包 WP-10：实现区域 PBF → PMTiles 构建链路。

下载到暂存路径并校验；大陆省份从同一中国快照按 .poly 提取，避免重复对象版本；使用固定 Planetiler 生成基础 OpenMapTiles 和高细节 POI；manifest 记录源序列、时间、成员、边界、输入/输出 SHA256、工具和构建时间。

只有暂存产品验证通过才原子激活并保留 .previous。取消、磁盘不足、哈希失败和构建失败必须保留当前版。
验收：Plan 无副作用；Build、Verify、Update、Rebuild、Rollback、Enable/Disable 和带确认令牌的 Remove 都有状态机测试。
```

#### WP-11 全球概览和 PMTiles 传输

```text
工作包 WP-11：实现 z0-7 本地全球概览和 PMTiles Range 服务。

用 Natural Earth 110m/50m/10m 构建陆地、水体、国省界、城市、主要道路、铁路和河流的世界 PMTiles。构建到 staged，验证文件头和最小体积后激活，manifest 保存 SHA256。nginx 对所有 PMTiles 返回正确的 206、Content-Range 和缓存验证信息。

验收：随机首段/中段/尾段 Range 请求正确；更新归档后旧字节缓存不复用；没有区域包时全球概览仍可浏览。
```

#### WP-12 MapLibre 主地图骨架

```text
工作包 WP-12：实现主地图来源切换和确定性回退。

提供本地 Carto、区域 PMTiles、全球概览、OSM Standard 和 OpenFreeMap。多个已安装区域同时加载，区域快捷方式只移动镜头。在线源只有用户明确选择时访问当前视口；失败时按备用在线源 → 本地概览回退。来源切换不得重建整个 MapLibre 实例。

实现覆盖判断，避免海岸、海洋、反经线和低缩放误弹安装提示；z8 以下默认隐藏自动建议。
```

### 6.3 测试数据矩阵

最小 fixture 必须包含：

- 区域：江苏、安徽、山东，以及未安装区域；
- 全球定位：日本、美国、台湾省、海岸外、纯海洋和反经线两侧；
- 文本：简体中文、英文、混合语言、emoji、引号、通配符和空白；
- 几何：点、短轨迹、多段轨迹、边界点、非法纬度/经度和空几何；

- 服务：全部就绪、单服务失效、数据过期、缺少一个启用区域和只有多余旧范围；
- 产品：current、previous、staged、损坏 manifest、字节漂移和哈希失败；
- 恢复：正常包、缺失文件、额外文件、路径穿越、大小变化和单字节篡改。

测试数据不得包含真实个人资料，必须可重复创建并在 `finally` 中清理。

### 6.4 性能和 I/O 验收建议

不要直接复制另一台机器的绝对时间。先在目标硬件用三个全新浏览器上下文和至少 30 次 API/Range 请求建立中位数与 p95，再使用以下相对门槛：

- 启动 `map-packs` 请求数必须等于 1；
- DOM、canvas、system-ready 中位数相对已批准基线退化不超过 25%；
- p95 PMTiles 1 MiB 随机 Range 延迟相对基线退化不超过 30%；
- cached inventory p95 不应被完整磁盘扫描阻塞；
- 并发浏览时维护状态仍能在其轮询周期内返回；
- 16 GiB 主机上 Valhalla 与 Nominatim 构建必须串行，不能依靠交换内存“通过”。

绝对 guardrail 应在目标机器测量后写入 `tests/performance-baseline.json`，并记录磁盘类型、可用内存、Docker 版本、数据规模和测试时间。

- 能力矩阵每一行都有实现位置和自动化测试；
